# FinJev 核心金融标注集 v0.1

这是一份从《明阳智慧能源集团股份公司 2025 年年度报告》中抽取的核心金融证据集。它不是 278 页逐页标注，也不是已经由两名金融分析师审定的 gold set，而是后续人工复核的 `seed set`。

## 当前范围

我只保留了最可能影响财务判断的 54 页：

| PDF 页码 | 内容 | 选择理由 |
| --- | --- | --- |
| 8–11 | 主要会计数据、季度数据、非经常性损益、公允价值 | 先判断利润、现金流和利润质量 |
| 23–34 | 经营、毛利、产销存、研发、资产负债、受限资产、投资 | 判断增长是否转化为现金和可持续利润 |
| 55–60 | 分红、股权激励、员工持股、内控 | 判断资本分配、稀释和控制质量 |
| 73–83 | 审计机构、诉讼、关联交易、担保、理财、募集资金、融资 | 判断或有负债、执行和再融资风险 |
| 94–114 | 审计意见、关键审计事项、三大报表、权益变动 | 用高权重财务证据交叉核验前面的摘要表 |

页码是 PDF 中报告标出的页码，例如第 8 页显示 `8 / 278`。原始 PDF 不复制进仓库，清单通过 `source_path` 和 SHA-256 记录来源。

## 输出文件

- `pages.jsonl`：54 条页级证据池记录。包含原文、标准化文本、页级 hash、抽取状态和视觉核对状态。
- `annotations.jsonl`：34 条句子/表行级金融标注。每条记录保留原始摘录、数值事实、风险标签、重要性和后续动作。
- `label_schema.json`：字段和枚举约束。
- `labeling_rules.md`：详细标注规则、阈值和人工复核流程。
- `manifest.json`：来源、页范围、数量、抽取器和版本信息。
- `validation_report.json`：摘录匹配和字段校验结果。

## 重新生成

在项目根目录执行：

```sh
uv sync
uv run --group dev python scripts/build_core_annotation_set.py \
  --source '/Users/Admin/Desktop/上市公司公告！！.pdf' \
  --output data/annotation_set_v0.1
```

构建脚本会对每条标注的 `source_excerpts` 做紧凑文本匹配。任何摘录不在对应 PDF 页中，构建会失败，不会悄悄生成不完整数据。

## 使用边界

这 34 条记录覆盖利润、现金流、毛利、存货、合同资产、短期借款、担保、理财、募集资金、审计事项和融资，但仍然只有一个发行人、一个年度报告。它可以验证 schema、规则和工作流，不能单独训练一个泛化的金融判断模型。

正式训练前必须至少补充：

1. 多个发行人、行业和年度，避免模型记住明阳智能的措辞。
2. 同一事件的正例、负例、无关例和冲突例。
3. 两名标注员独立标注后再仲裁，尤其是收入确认、减值、担保、诉讼和关联交易。
4. 按“公司/报告/时间”切分 train、validation、test，不能把同一张年报的相邻表行随机拆到训练集和测试集。

阈值是 FinJev 的任务策略，不是会计准则、监管认定或投资建议。`ACCEPT` 只表示“这个来源对该条披露主张足够支持”，不表示公司没有其他风险。
